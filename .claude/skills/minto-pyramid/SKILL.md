# Minto Pyramid

## Structure

```
Answer / Recommendation      ← lead with this; one sentence
├── Key argument 1           ← 2–4 supporting points, parallel in form
├── Key argument 2
└── Key argument 3
    ├── Evidence / data      ← facts, data, examples under each argument
    └── Evidence / data
```

The reader should be able to stop at any level and have a complete (if less detailed) picture.

## Two entry patterns

**BLUF (Bottom Line Up Front)** — when the audience already has context:
> [Answer]. [Key argument 1]. [Key argument 2]. [Key argument 3].

**SCQA** — when the audience needs situational grounding first:
- **Situation**: what is true and agreed upon
- **Complication**: what changed or what problem exists
- **Question**: what therefore needs to be answered
- **Answer**: the recommendation or conclusion

Use SCQA for cold readers (stakeholders unfamiliar with the background). Use BLUF for warm readers (teammates who know the context).

## Workflow

Given raw content or a topic:

1. **Identify the answer** — what is the single most important thing the reader should take away? State it in one sentence.

2. **Find the key arguments** — what are the 2–4 parallel reasons or findings that support the answer? These should be mutually exclusive and collectively exhaustive (MECE) where possible.

3. **Attach evidence** — under each key argument, list the facts, data, or examples that back it.

4. **Choose entry pattern** — BLUF or SCQA based on reader context.

5. **Draft** — write top-down: answer first, then arguments, then evidence.

## Output format

- Always show the pyramid structure explicitly before the prose draft, so the architecture is visible.
- Then write the actual text (email, doc section, etc.) in the chosen entry pattern.
- Keep the answer sentence to ≤25 words.
