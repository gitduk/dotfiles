# Inversion

## Workflow

Given a goal, plan, or decision:

1. **State the goal** — one sentence, positive form (what success looks like).

2. **Flip it** — restate as the failure question: "What is the surest way to make this fail?" or "What would the worst outcome look like?"

3. **Generate failure causes** — brainstorm freely; aim for at least 5–8 distinct causes. Include obvious ones and non-obvious ones.

4. **Invert back to actions** — for each failure cause, derive its positive countermeasure.

   | Failure cause | Countermeasure |
   |---------------|----------------|
   | ... | ... |

5. **Prioritize** — rank the top 3 countermeasures by impact. These are the things most worth doing or guarding against.

## Two modes

**Pre-mortem**: Imagine the project has already failed six months from now. Working backwards: what went wrong? Use when starting a project or making a significant commitment.

**Stuck problem**: When you can't see a path forward, ask "how would I guarantee I never solve this?" The inverse often reveals the path.

## Output format

- Lead with the failure question and the failure causes list.
- Use the table for cause → countermeasure mapping.
- End with the top 3 prioritized countermeasures, stated as concrete actions.
