[R01] 写代码前自上而下走极简阶梯：不需要就跳过、stdlib 能做就用、平台原生特性优先、已装依赖能做就用、能一行就一行，最后才写最少代码。
[R02] 听上去像要从零实现的请求（示例、边界、「写个函数…」）不是跳过阶梯的理由；先给阶梯答案，若像要手写版再补一行。
[R03] 信任边界的输入校验、防数据丢失的错误处理、安全措施、可访问性基础、以及明确要求的东西永不简化掉；用户坚持要完整版就照做。
[R04] 不可逆操作先查看（有可见输出）再执行，分两条命令，绝不把「看」和「删」合成一行。
[R05] `git checkout --`、`git restore`、`git reset --hard`、`git clean`、`git stash drop` 会永久销毁未提交改动；动手前先 `git status` + `git diff` 看会丢什么，有未提交修改就先 stash 或征得明确确认，绝不直接丢弃。
[R06] 对远程主机（SSH 或远程 shell）的 `kill`/`pkill`/`tmux kill-server`/`systemctl stop|restart`/`docker kill|stop`：先列出那个 session/主机实际在跑什么再决定，绝不未经确认就杀与目标共享 session/容器的进程。
[R07] 注释默认不写；写前自测「重构相邻代码会逼这注释改吗」——会则它在复述实现（删），不会则它描述代码外的约束（留）；存活者最多两行、每行一个约 80 字符内的短句。
[R08] 读到与代码不符的注释，在同一次编辑里修或删，哪怕在改动范围外；已知为假的注释比没有更糟。
[R09] 公共 API 的 docstring 是接口契约而非普通注释，「默认无注释」不适用于它们。
[R10] 同一对象在第二个测试文件里需要完整构造的那一刻，抽成共享 fixture/factory，而不是写第三份内联拷贝。
[R11] 项目代码绝不写 `./` CWD 相对路径——换目录启动就崩；shell 命令同样，显式固定 base（`git -C <dir>`），别信 shell 落在哪。
[R12] TLS 证书校验保持开启，绝不 `verify=False`、`danger_accept_invalid_certs(true)` 或任何语言的等价物。
[R13] 格式化归 git pre-commit hook 管，绝不手动跑格式化器。
[R14] 只有存在测试套件时才跑对应语言的测试命令。
[R15] 解释「为什么/怎么发生」前先验证，查不到就标「未查证，推测是…」，别把猜测当事实陈述。
[R16] 中文标点：剥掉内嵌代码/英文/数字后句子仍是中文就用全角（，。？！：；、「」（）——），紧邻代码不是用半角的理由。
[R17] 半角标点只用于真正的代码语法：反引号代码块、标识符、文件路径、版本号、URL、逐字引用。
[R18] 相邻代码块之间的分隔符算代码语法，保持半角。
[R19] 标点风格在同一文档内必须统一。
[R20] 除非上下文是纯英文代码/文档，否则用中文回复。
[R21] 代码注释用英文写。
[R22] 剪贴板用 `wl-copy`。
[R23] JS 包管理器优先 `bun` 而非 `npm`；若项目已有 `package-lock.json` 且无 bun lockfile 则用 `npm`。
[R24] HTTP 客户端优先 `xh` 而非 `curl`。
[R25] 代码注释不得超过三行，超长就精简或删掉。
